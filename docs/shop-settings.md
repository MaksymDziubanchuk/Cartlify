# Shop settings

This page explains the data of the shop that root changes without a deploy, to a developer who builds the frontend and to the shop owner. The routes, the fields and the error codes are also in [API](api.md) and in Swagger (`/documentation`); the languages the shop answers in have their own page, [languages](languages.md).

## A table of versions, not an environment variable

Delivery, the brand of a mail, the minutes a reservation and a payment page last, the check of a review's comment, how many removals by a moderator the rules allow, the days of grace after the right to withdraw, the logo and the languages the shop answers in: all of this used to be an environment variable, read once when the server started and changed only by a new deploy. It now lives in one database table, `shop_settings`, and root changes it from the admin pages while the server runs.

The table is **append-only**: a write is never an update, it is a new row with every field named, and the current data of the shop is simply the row with the highest `version`. No role, not even root, may change or remove a row once it exists (the database refuses an `UPDATE` or a `DELETE` on it with `SHOP_SETTINGS_APPEND_ONLY`, besides the row policies that already deny it); so does root's own request: `PUT /api/root/shop-settings` only ever adds a row. The server keeps the current row in memory and reads it everywhere a route used to read `process.env` (`shopSettings()`, `src/config/shopSettings.ts`); it reloads it once when it starts and again right after every write, so a change by root is live for the next request, no restart needed. The copy in memory is one per server process: the shop runs as one instance today; a second instance would keep its own copy until it restarts, so running more than one needs the copy shared or reloaded first.

**Writing a version.** Root sends every field at once, not a partial change, together with `baseVersion`: the version root was looking at when they opened the form to edit (`items[0].version` of `GET /api/root/shop-settings/history?limit=1`; `0` before any version exists). If another write reached the database first, root's own write is refused with `409 SHOP_SETTINGS_OUTDATED`, naming the `baseVersion` root sent; the frontend reads the current version again and asks root to edit from it. The database decides this (`cartlify.shop_settings_before_insert`, an advisory lock keeps two writes at once from racing): a write with no `baseVersion` at all (the server filling in a field left empty, see below) skips the check, because it only fills a gap and can never conflict with a choice root is making.

**Who reads what.** `GET /api/shop-settings` is open to everybody (a guest, a buyer): the fields the site itself needs to show the shop's brand, its logo and the languages it offers, and the seller it must name on the pages and documents that EU law asks for — delivery is its own route, [`GET /api/delivery/methods`](api.md). `GET /api/admin/shop-settings` gives an admin or root every field of the current version but the internal id of the logo file at Cloudinary, and `GET /api/admin/shop-settings/:key` gives one field on its own (the key is checked against the real list of fields, an unknown one is `400 VALIDATION_ERROR` before anything is read). Only root sees the history (`GET /api/root/shop-settings/history`, a page of versions, the latest first, each with who wrote it: a root's name and email, or `null` for a row the server itself added to fill in a default — a deleted root's own writes keep the name they used, not the address).

## The fields

| Field                 | Type and bounds                                                                                                                                                          | Default                                                      | Public  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ | ------- |
| `deliveryMethods`     | list of `manual`, `pickup`, no repeats                                                                                                                                   | `['manual']`                                                 | no      |
| `deliveryFlatPrice`   | money, above 0 to the cent, at most 99999999.99                                                                                                                          | none                                                         | no      |
| `deliveryFreeFrom`    | money, above 0 to the cent, at most 99999999.99 (needs `deliveryFlatPrice` too)                                                                                          | none                                                         | no      |
| `deliveryCountries`   | list of ISO 3166 alpha-2 codes, no repeats, each one the app knows how to take a postal code of                                                                          | **none**                                                     | no      |
| `pickupAddress`       | text, up to 300 characters, required (not blank) once `pickup` is a delivery method                                                                                      | `''`                                                         | no      |
| `pickupHours`         | text, up to 300 characters, required (not blank) once `pickup` is a delivery method                                                                                      | `''`                                                         | no      |
| `shopName`            | text, up to 100 characters                                                                                                                                               | `'Cartlify'`                                                 | **yes** |
| `emailFromName`       | text, up to 100 characters                                                                                                                                               | `''`                                                         | no      |
| `emailReplyTo`        | an email address, up to 254 characters; **no mail goes out while it is empty**                                                                                           | `''` (counted as not set)                                    | no      |
| `logoUrl`             | the Cloudinary address of the logo (its own routes write it, see below)                                                                                                  | **none**                                                     | **yes** |
| `reservationMinutes`  | whole minutes, above 0                                                                                                                                                   | `15`                                                         | no      |
| `stripePageMinutes`   | whole minutes, at least 30 (Stripe never keeps a page open for less); together with `reservationMinutes`, at most 1440 (Stripe never keeps one open for more than a day) | `30`                                                         | no      |
| `reviewCheckEnabled`  | boolean                                                                                                                                                                  | `true`                                                       | no      |
| `avatarRemovalsLimit` | whole number, above 0                                                                                                                                                    | `5`                                                          | no      |
| `reviewRemovalsLimit` | whole number, above 0                                                                                                                                                    | `5`                                                          | no      |
| `withdrawalGraceDays` | whole number, 0 to 30                                                                                                                                                    | `4`                                                          | no      |
| `shopLocale`          | two lower-case letters, one of `enabledLocales`                                                                                                                          | `'en'`                                                       | **yes** |
| `enabledLocales`      | list of two lower-case letters, no repeats, each with a dictionary file                                                                                                  | every language with a dictionary ([languages](languages.md)) | **yes** |
| `sellerLegalName`     | text, up to 200 characters                                                                                                                                               | **none**                                                     | **yes** |
| `sellerAddress`       | text, up to 500 characters                                                                                                                                               | **none**                                                     | **yes** |
| `sellerTaxId`         | text, up to 50 characters                                                                                                                                                | **none**                                                     | **yes** |
| `sellerEmail`         | an email address, up to 254 characters                                                                                                                                   | **none**                                                     | **yes** |
| `sellerPhone`         | text, up to 30 characters                                                                                                                                                | **none**                                                     | **yes** |

The shape of a value is a column `CHECK` of the database (`db/schema/06_indexes_and_constraints.sql`); a list's shape (no two values alike, a pattern each one matches) is a plain SQL function, because a `CHECK` cannot hold a subquery. `PUT /api/root/shop-settings` checks every rule itself before it writes anything, so a mistake of root comes back as a `400` that names it rather than as a refusal of the database: a value out of its shape (a price not above zero, below the cent or over the most the column holds, a list naming a value twice, a reply-to or a seller email that is not an address) is `400 VALIDATION_ERROR`; the rules between fields have codes of their own: `DELIVERY_FREE_FROM_WITHOUT_PRICE` (a free-from with no price), `PICKUP_DETAILS_REQUIRED` (the pickup method on with a blank address or hours, `details.fields` the blank ones; the database alone would let an empty text through), `RESERVATION_MINUTES_TOO_LONG` (the reservation and the page together over a day, `details.max`) and `SHOP_LOCALE_NOT_ENABLED` (`shopLocale` not among `enabledLocales`). Two more are lists the app itself keeps, which the database cannot know: a country of `deliveryCountries` the app does not actually know how to take a postal code of (`400 DELIVERY_COUNTRY_NOT_SUPPORTED`, `details.countries` the ones refused, `details.supported` the full list) and a language of `enabledLocales` with no dictionary file (`400 LOCALE_NOT_SUPPORTED`, `details.locales`/`details.supported`, see [languages](languages.md)).

## A field with no default

Most fields have a default: until root writes a version of their own, the server fills the field with the same value the code used to have, so nothing changes the day this table replaced the environment variables. Seven fields have **no** default at all, bold above: `deliveryCountries`, `logoUrl` and the five fields of the seller. `emailReplyTo` has one, but an empty one the shop cannot work with: no mail goes out without an address to reply to (the mail itself names it as the one to write to), so while it is blank it counts as not set, the same as these seven. Until root sets one of these:

- the start of the server does not stop, and no field anywhere falls back to a made-up value;
- a request that genuinely needs it is refused with its own error code instead (confirming an order of the manual delivery method needs `deliveryCountries`, for instance);
- root and the admins see it on the alert `shop_settings_incomplete`, which stays lit for as long as any of these eight fields is empty (`GET /api/admin/shop-settings/missing` names exactly which, the same list the alert counts);
- a mail or a page that only _names_ the seller or the shop simply says less, it is never a reason to refuse anything on its own; the one exception is `emailReplyTo`: every mail is refused while it is empty (`EMAIL_REPLY_TO_REQUIRED` in the log of the server).

The server fills a field that **does** have a default, and one newly added to the code later that nobody has written yet, by itself: the very first time it starts after such a field appears empty, it writes one more version with that field (and only that field) set to its default, under the system's own name rather than root's (`setBy: null` in the history). This keeps `shopSettings()` simple — it is always the latest row, defaults already baked in — and means a developer adding a new field with a default never has to ask root to go and set it first.

## Languages

`shopLocale` and `enabledLocales` decide which language a guest's mail, the chat bot and the Stripe payment page use when nobody has a language of their own (and `enabledLocales`, together with a dictionary file per language, decides which language a signed-in person is even allowed to pick). The full model — the dictionaries, how a person's own language is chosen, and how to add a new one — is [languages](languages.md); `shop_locale_missing` is the alert for when `shopLocale` names a language whose dictionary file was removed by a later deploy (mail still goes out, in English, until root picks another language that still has one).

## The logo

The logo is not among the fields `PUT /api/root/shop-settings` writes: it has two routes of its own, because uploading a file is not a plain edit of a form that could go stale against another root's edit the way the rest of the fields can. `POST /api/root/shop-settings/logo` takes a form with one file, `image` (a jpeg, png or webp file, checked by its content, not by the name or the type the browser sent), uploads it to Cloudinary, deletes the old file if there was one, and writes a new version with the rest of the fields carried forward unchanged; `DELETE /api/root/shop-settings/logo` takes it off the same way (`409 SHOP_LOGO_NOT_SET` when there already is none). A write that races a plain `PUT` (the version moved between reading it and inserting the new row) is retried, up to three times, with the version that got there first.

Without a logo the shop's mails simply go out without one (the template shows the shop's name in text instead), never a reason to refuse sending a mail. When there is one, `src/services/email/shopLogo.ts` fetches the file from `logoUrl` and keeps it in memory as long as that address does not change (a new upload always gets a new address, so the cache can never show a stale file); a fetch that takes more than 8 seconds, or fails outright, is logged and the mail goes out without the logo; the mails of the next minute then go without it at once, rather than each waiting the 8 seconds again while Cloudinary is out of reach.

## Routes

| Route                                  | Who         | What                                                                                  |
| -------------------------------------- | ----------- | ------------------------------------------------------------------------------------- |
| `GET /api/shop-settings`               | everybody   | the public fields                                                                     |
| `GET /api/admin/shop-settings`         | admin, root | every field of the current version but the logo's internal Cloudinary id              |
| `GET /api/admin/shop-settings/missing` | admin, root | the fields with no default that are still empty, and `emailReplyTo` while it is blank |
| `GET /api/admin/shop-settings/:key`    | admin, root | one field of the current version on its own                                           |
| `PUT /api/root/shop-settings`          | root        | writes a new version, every field at once, with `baseVersion`                         |
| `GET /api/root/shop-settings/history`  | root        | every version, the latest first, who wrote each                                       |
| `POST /api/root/shop-settings/logo`    | root        | sets or replaces the logo                                                             |
| `DELETE /api/root/shop-settings/logo`  | root        | takes the logo off                                                                    |

## After a deploy

The variables these fields replaced are gone from `src/config/env.ts` and `.env.example` for good — they are not read as a fallback, there is no transition period. A deploy that brings this table for the first time needs root to open the admin pages and fill in, at least, `emailReplyTo` (without it no mail goes out at all) and the fields with no default (`deliveryCountries` above all: without it the manual delivery method, if it is on, refuses every order); until then the `shop_settings_incomplete` alert says so. See [configuration](configuration.md) for what is left in the environment and why.
